# Football Search App

The Football Search App lets you search football competitions, teams and matches using the football-data API. This README focuses on quick setup, environment handling, running a local proxy (recommended) and common troubleshooting (CORS / 403).

## Quick summary

- Frontend: static files in project root (`index.html`, `src/`).
- Optional local proxy: `server/` (forwards to the external API and attaches API keys server-side).
- Local browser env helper: `src/env.local.js` generated by `npm run generate-env` (creates `window._env_.API_KEY` for dev).

## Prerequisites

- Node.js (14+)
- npm
- An API key for the football-data API (or the API you are using)

## Environment / API key

Recommended: do not embed API keys in frontend code. Run a small local proxy that attaches the API key server-side, or generate a browser-safe env file for local development.

Generate browser-safe env:
- Create a `.env` in project root or `src/.env` containing your key, e.g.
  ```
  API_KEY=your_api_key_here
  ```
- Run:
  ```
  npm run generate-env
  ```
  This writes `src/env.local.js` (browser-safe) containing `window._env_.API_KEY`. Do not commit this file.

Note: For production, use a server-side proxy and do not expose API keys to the browser.

## Start local proxy (recommended)

If the project includes a `server/` proxy, use it to avoid CORS and to keep your API key secret.

1. Install and configure server env:
   - Copy `server/.env.example` → `server/.env` and set the API key and PORT.
2. Start the proxy:
   ```
   cd server
   npm install
   npm run dev   # or npm start
   ```
3. The proxy forwards requests from `http://localhost:3000/api/...` to the external API and attaches the auth header.

When the proxy is running, point the frontend API base to it (the app expects the proxy route at `/api` by default).

## Serve the frontend

Serve the project directory over HTTP (do NOT open `file://`), e.g.:

- Using `serve`:
  ```
  npx serve .
  ```
- Or using Python:
  ```
  python -m http.server 8000
  ```

Open `http://localhost:8000` (or the port your server uses).

## Common troubleshooting

- 403 Forbidden when fetching matches (e.g. GET /v4/teams/770/matches)
  - Ensure the request includes a valid `X-Auth-Token`. If using a proxy, make sure the proxy is attaching the token correctly.
  - If you see 403 from the proxy but direct requests succeed, inspect the proxy logs to confirm headers are forwarded.
  - If you are not running a proxy, ensure `src/env.local.js` (generated via `npm run generate-env`) contains the API key under `window._env_.API_KEY` and the frontend is reading that value.

- CORS / Origin mismatch
  - Serve the frontend from `http://localhost` (not `file://`) or run the proxy on localhost so API calls come from an allowed origin.
  - If you cannot run a proxy, you may need to configure CORS on the server side or use a development proxy.

- Rate limiting (429)
  - The app retries a few times when receiving 429 with exponential backoff. If you hit rate limits frequently, reduce request frequency or upgrade API plan.

## Dev notes

- Generate env for the browser: `npm run generate-env`
- Start proxy (if available): `cd server && npm run dev`
- Serve static frontend: `npx serve .` or `python -m http.server 8000`
- If you modify `src/generate-env.js` behavior, prefer creating a `.cjs` version when using `type: "module"` in package.json, or keep package.json default CommonJS behavior.

## Debugging tips

- Open DevTools Console to see debug logs from `src/index.js` (fetch URLs and headers are logged in development mode).
- If a request returns 403, check both:
  - whether the outgoing request includes `X-Auth-Token`
  - whether a proxy is stripping or overriding headers
